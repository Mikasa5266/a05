# 后端工程师 - 系统设计与架构（知识点 + 题库）

## 一、知识点部分（问题 + 解析）

### 1. 微服务与单体架构的核心权衡是什么？
**解析：**
微服务带来独立部署与团队自治，但引入分布式复杂性；单体开发运维简单，但扩展性和组织协同受限。架构选择应匹配团队规模和业务阶段，而非追随潮流。

### 2. 消息队列在系统中的价值有哪些？
**解析：**
核心价值是削峰、解耦、异步化和最终一致性。引入 MQ 后要同步考虑消息丢失、重复消费、顺序性和堆积治理。

### 3. 秒杀系统为什么容易超卖？
**解析：**
超卖根因是并发读写竞争和库存扣减非原子。常见策略是预扣库存、原子扣减、幂等下单、限流与排队、异步落库。

### 4. RESTful API 设计如何兼顾易用与演进？
**解析：**
应保持资源语义清晰、HTTP 方法正确、状态码规范、版本管理明确，并提供稳定的错误码体系。接口设计要预留演进空间，避免一次性写死。

### 5. Session、JWT、OAuth2 分别适用哪些场景？
**解析：**
Session 适合单域服务端会话；JWT 适合跨服务无状态认证；OAuth2 适合第三方授权。选择要结合安全性、可撤销性和网关治理能力。

### 简答题 1：请设计一个高并发下单系统的核心链路。
**参考答案：**
链路可为：网关限流 -> 资格校验 -> 预扣库存（缓存原子操作）-> 消息队列异步下单 -> 数据库落单 -> 结果回查。并配套幂等键、防重、超时补偿和死信队列。

**答案解析：** 该题高分点在抗压能力 + 一致性兜底 + 故障可恢复。

### 简答题 2：如何做分布式系统的可观测性建设？
**参考答案：**
- 日志：结构化、可检索、可关联 trace-id；
- 指标：QPS、错误率、延迟分位数、资源使用；
- 链路：全链路追踪定位慢点与失败点；
- 告警：分级告警和自动化处置策略。

**答案解析：** 可观测性不是多打日志，而是能支撑定位、评估与决策闭环。

### 简答题 3：请设计一个“下单-支付-库存”最终一致方案。
**参考答案：**
可采用本地事务 + 可靠消息：下单成功后写消息表，异步投递支付/库存事件，消费端幂等处理并回传状态，失败通过重试与补偿任务修复。

**答案解析：** 该题关键在“可靠事件 + 幂等消费 + 补偿闭环”。

### 简答题 4：如何做 API 版本演进，避免破坏旧客户端？
**参考答案：**
采用显式版本策略（URL/Header），保持旧版本兼容窗口，新增字段尽量向后兼容，删除字段需经过灰度和公告周期。

**答案解析：** 版本治理考察工程规范与服务稳定性意识。

### 简答题 5：请给出高并发系统容量评估的基本方法。
**参考答案：**
根据峰值 QPS、平均耗时、并发连接、依赖服务能力和冗余系数做估算，并通过压测校准模型，预留扩容阈值与自动伸缩策略。

**答案解析：** 容量评估不是拍脑袋，要有“估算-压测-回归”闭环。

### 简答题 6：服务雪崩发生时，你的应急处理顺序是什么？
**参考答案：**
先限流止血 -> 开启降级与熔断 -> 隔离故障依赖 -> 扩容关键节点 -> 回放监控定位根因 -> 修复并复盘。

**答案解析：** 高压场景下“先止血后根因”是标准处置方法。

## 三、扩展知识点（问题 + 解析）

### 6. 为什么系统设计要先定义“非功能性指标”？
**解析：**
性能、可用性、安全性、成本是架构边界条件。若不先定义指标，方案讨论容易失焦，最终难以验收。

### 7. 领域拆分不合理会带来什么长期问题？
**解析：**
会导致服务边界模糊、跨服务强依赖、发布耦合和团队职责冲突。领域边界是微服务治理的第一性问题。

### 8. 为什么“异步化”不能滥用？
**解析：**
异步能提升吞吐，但会增加一致性、可观测性和故障排查复杂度。应优先异步化非关键链路，并配套补偿机制。

### 9. API 网关为什么要做配额治理？
**解析：**
不同租户和业务线流量差异大。配额治理可防止单租户抢占资源，保障平台公平性和稳定性。

### 10. 为什么“降级策略”要按业务等级预先定义？
**解析：**
故障来临时再临时决策容易混乱。预定义可确保核心功能优先、非核心功能可快速关闭，缩短故障处置时间。

### 11. 多活架构真正难点是什么？
**解析：**
难点不在部署多个机房，而在跨地域数据一致性、流量调度、故障切换和回切策略的工程化落地。

### 12. 为什么说可观测性是架构能力而不是运维附加项？
**解析：**
没有可观测性就无法判断系统行为是否符合设计。可观测性应在架构阶段内建，而不是上线后补丁式追加。

### 13. 成本优化在系统设计中应如何落地？
**解析：**
通过分层存储、分级服务、冷热分离、弹性扩缩容和峰谷调度控制成本，避免单纯追求“技术最优”导致预算失控。

### 简答题 8：如何构建系统级故障演练机制？
**参考答案：**
定义演练场景（依赖超时、机房故障、流量洪峰）-> 设定观测指标 -> 小范围演练 -> 复盘改进 -> 固化为常规机制。

**答案解析：** 演练价值在于验证预案有效性，而不是走流程。

### 简答题 9：请给出秒杀系统“防超卖 + 防刷”组合设计。
**参考答案：**

**答案解析：** 秒杀治理必须同时覆盖“正确性”和“流量安全”。

### 简答题 10：如何评估一项架构改造是否值得做？
**参考答案：**
评估业务收益、风险下降幅度、实施成本、迁移复杂度、团队能力匹配和回滚可行性，形成量化 ROI 结论。

**答案解析：** 架构改造应面向业务价值，而非技术炫技。

**参考答案：**
围绕用户旅程建立关键指标，打通日志-指标-追踪关联，减少无效噪声指标，强化异常样本回放能力。

**答案解析：** 可观测性重在“可定位”，不是“指标数量”。

### 简答题 13：请说明你会如何做微服务拆分边界评估。
**参考答案：**
按业务领域、数据归属、变更频率、团队边界、依赖关系做评估；优先拆分高内聚低耦合模块，并规划过渡期治理策略。

**答案解析：** 拆分边界合理性决定后续治理成本。

### 简答题 14：如何设计跨团队接口协作机制？
**参考答案：**
统一接口规范、变更评审、版本策略、兼容窗口、联调排期和回归用例，确保跨团队变更可控。

**答案解析：** 协作机制能显著降低跨团队集成风险。

### 简答题 15：请给出“服务从单体到微服务”的迁移路线。
**参考答案：**
先做模块化与接口边界清理 -> 拆出外围低风险服务 -> 建立网关和治理基础设施 -> 逐步迁移核心链路 -> 持续压测与复盘。

**答案解析：** 渐进式迁移比一次性重构风险更低。

### 简答题 16：如何平衡架构先进性与团队可维护性？
**参考答案：**
优先选择团队可掌握、可演进、可排障的方案；新技术先试点验证，再规模化落地，避免认知债务过快累积。

**答案解析：** 架构的长期价值取决于团队可持续维护能力。
