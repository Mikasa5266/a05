# 后端工程师 - 数据库（知识点 + 题库）

## 一、知识点部分（问题 + 解析）

### 1. 为什么 MySQL 索引常用 B+ 树而不是 B 树？
**解析：**
B+ 树非叶子节点只存键，单页可容纳更多指针，树更矮，磁盘 I/O 更少；叶子节点顺序链表天然支持范围查询。数据库索引设计核心目标是减少随机 I/O，而不是纯内存场景下的比较次数。

### 2. 事务隔离级别与并发问题的对应关系是什么？
**解析：**
- 读未提交：可能脏读；
- 读已提交：避免脏读，但有不可重复读；
- 可重复读：避免不可重复读，仍可能幻读（MySQL 通过 MVCC+间隙锁缓解）；
- 串行化：最强隔离，吞吐最低。
隔离越强并发越低，需按业务一致性要求做权衡。

### 3. 缓存穿透、击穿、雪崩如何区分？
**解析：**
- 穿透：请求不存在数据，绕过缓存直击数据库；
- 击穿：热点 key 过期瞬间大量并发打到 DB；
- 雪崩：大面积 key 同时失效导致系统抖动。
治理要分层：布隆过滤、互斥重建、过期时间打散、多级缓存与限流降级。

### 4. Redis 分布式锁为什么要考虑续期和误删？
**解析：**
业务执行时间超过锁 TTL 会导致锁提前失效。续期机制可避免长任务误释放。释放时必须校验 value，防止 A 线程删掉 B 线程的新锁。

### 5. SQL 优化为何先看执行计划而不是先改代码？
**解析：**
慢 SQL 的根因常在索引失效、回表过多、连接顺序不佳。EXPLAIN 能直观看到扫描行数与访问类型。先定位再优化，比盲调更高效。

## 二、题库部分（单选题 + 简答题）

C. 关闭缓存

### 简答题 1：请设计一个缓存 + 数据库一致性方案。
**参考答案：**
可采用旁路缓存 + 延迟双删 + 重试补偿策略：
1. 写请求先更新数据库；
2. 删除缓存；
3. 异步延迟再次删缓存，处理并发读写竞争；
4. 配合消息队列与重试保障最终一致性。

**答案解析：** 该题重点是并发竞态处理。只说先删缓存再写库通常会引发脏数据窗口。

### 简答题 2：发现某 SQL 突然变慢，你如何排查？
**参考答案：**
- 看慢日志与执行计划；
- 看索引命中、扫描行数、回表情况；
- 看统计信息是否失真；
- 看是否受锁等待和资源争用影响。

**答案解析：** 优秀回答应覆盖查询计划 + 资源层 + 并发层，体现系统化诊断能力。

### 简答题 3：请说明 MVCC 的核心思想及收益。
**参考答案：**
MVCC 通过多版本快照实现“读不阻塞写、写不阻塞读”的并发控制。读事务读取一致性视图，写事务生成新版本并通过 undo log 管理历史版本。

**答案解析：** 该题考察事务底层机制理解，回答应同时覆盖“版本链 + 可见性规则”。

### 简答题 4：如何设计一个高可用 Redis 缓存架构？
**参考答案：**
可采用主从 + 哨兵或集群模式，配套持久化策略、热点 key 保护、降级回源和监控告警；同时准备故障演练与容量评估机制。

**答案解析：** 高可用不等于“有主从”，还包括治理、演练和容量规划。

### 简答题 5：深分页为什么慢？常见优化方案有哪些？
**参考答案：**
深分页会跳过大量记录导致扫描成本高。优化可用：
1. 基于主键游标分页；
2. 覆盖索引减少回表；
3. 预计算或搜索引擎分担。

**答案解析：** 该题重点是理解“跳过成本”，而不是只记 `limit offset` 语法。

### 简答题 6：请给出一套数据库慢查询治理流程。
**参考答案：**
采集慢日志 -> 聚类高频 SQL -> 执行计划分析 -> 索引/SQL 重写 -> 压测验证 -> 灰度上线 -> 持续监控回归。

**答案解析：** 治理流程化是数据库性能优化成熟度的重要体现。

## 三、扩展知识点（问题 + 解析）

### 6. 为什么数据库连接池参数配置不当会拖垮服务？
**解析：**
连接池过小会造成排队和超时，过大则可能压垮数据库。应基于数据库实例能力、请求并发、SQL 平均耗时做容量预算，并设置获取连接超时。

### 7. 读写分离架构下如何处理一致性读？
**解析：**
关键写后读场景可走主库或延迟路由策略（例如一定时间内走主库），避免从库延迟导致用户“刚写就读不到”。

### 8. 为什么“索引多”不一定是好事？
**解析：**
索引会占空间并增加写放大。每次写入都需维护相关索引，过多索引会降低写性能。索引设计应以查询收益覆盖维护成本为原则。

### 9. 分库分表后最常见的新问题是什么？
**解析：**
跨分片事务、跨分片聚合、分页排序和扩容迁移复杂度显著上升。分库分表不是“性能银弹”，是用架构复杂度换容量上限。

### 10. 为什么在线 DDL 变更需要灰度和回滚预案？
**解析：**
表结构变更可能引发锁等待、长事务阻塞和兼容性问题。应先评估影响范围，使用在线变更工具并准备回滚方案。

### 11. 数据库审计日志在生产治理中的价值是什么？
**解析：**
审计日志可追溯高风险操作、定位数据异常来源、支持合规审查，是生产安全治理的重要组成。

### 12. 为什么“冷热数据分层”能提升整体性价比？
**解析：**
热数据保留在高性能存储，冷数据归档到低成本介质，既保障在线性能，又控制存储成本。

### 13. 数据库高可用方案中，故障切换为什么容易引入“脑裂风险”？
**解析：**
若主从角色判定不一致，可能出现双主写入。需依赖一致性判断、仲裁机制和严格的切换流程避免数据分叉。

### 简答题 7：请设计一套“写后读一致性”保障方案。
**参考答案：**
可采用关键写后读走主库、短期路由粘性、版本号校验和重试兜底；对非关键读允许最终一致。

**答案解析：** 一致性策略应按业务关键程度分级，而非全局一刀切。

### 简答题 8：如何做 Redis 热点 key 治理？
**参考答案：**
热点识别 -> 预热与多副本分散 -> 本地缓存兜底 -> 限流熔断 -> 监控告警。必要时对热点请求做异步化与结果缓存。

**答案解析：** 热点治理强调“识别 + 缓解 + 兜底”闭环。

### 简答题 9：请给出分库分表后的分页查询优化思路。
**参考答案：**
优先业务维度缩小分片范围，采用游标分页替代深分页，必要时引入汇总索引或搜索引擎做跨分片聚合。

**答案解析：** 分片场景下分页难点在全局有序与跨片聚合成本。

### 简答题 10：如何设计数据库备份与恢复演练机制？
**参考答案：**
设定备份频率与保留策略，定期做全量+增量恢复演练，验证恢复时间和数据完整性，形成演练报告与改进项。

**答案解析：** 备份有效性必须通过恢复演练验证，不能只看“备份成功”。

### 简答题 11：请说明“事务隔离级别选择”的决策方法。
**参考答案：**
按业务一致性需求、并发量、可接受异常类型来选择。关键交易优先一致性，普通查询优先吞吐，并辅以业务幂等与补偿。

**答案解析：** 隔离级别没有绝对最优，需结合业务目标做权衡。

### 简答题 12：如何建立数据库容量治理体系？
**参考答案：**
建立容量模型（QPS、连接数、存储增长）、预警阈值、扩容流程和压测回归机制，按季度复盘预测偏差。

**答案解析：** 容量治理是持续工程，不是临时扩容行为。

### 简答题 13：数据库出现主从延迟突增，你会如何应急？
**参考答案：**
先识别是否大事务或慢 SQL 导致 -> 降低从库压力 -> 关键读回主库 -> 处理积压日志 -> 恢复后复盘延迟根因。

**答案解析：** 应急顺序应先保障用户体验，再处理根因。

### 简答题 14：如何让 SQL 评审制度真正有效？
**参考答案：**
建立评审清单（索引、扫描行数、事务范围、回滚风险），配合自动化检查和压测门禁，避免评审流于形式。

**答案解析：** 有效制度依赖“标准 + 工具 + 反馈”三要素。

### 简答题 15：请给出数据库慢查询平台的核心能力清单。
**参考答案：**
SQL 聚类、执行计划快照、趋势分析、归因标签、告警分级、修复建议和效果回归评估。

**答案解析：** 慢查询平台应支撑发现、分析、修复、验证全流程。

### 简答题 16：如何在数据库治理中平衡“性能优化”和“开发效率”？
**参考答案：**
先治理高收益场景（TOP 慢 SQL、核心交易链路），将优化规则产品化（模板、lint、审查工具），把经验沉淀为标准流程。

**答案解析：** 通过平台化和标准化，才能长期兼顾效率与质量。
