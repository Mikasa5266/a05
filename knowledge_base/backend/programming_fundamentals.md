# 后端工程师 - 编程基础（知识点 + 题库）

## 一、知识点部分（问题 + 解析）

### 1. 为什么说数据结构决定算法上限？
**解析：**
相同业务目标，选择不同数据结构会导致复杂度阶跃变化。例如查找用数组 O(n)，用哈希可接近 O(1)。工程优化常先从结构选型入手。

### 2. 排序算法在工程中如何选型？
**解析：**
要看数据规模、是否近乎有序、是否要求稳定、内存限制。小规模常用插入排序，通用场景多用快排/归并/TimSort，外排序用于超大数据集。

### 3. 单例模式在并发场景下的风险是什么？
**解析：**
风险在初始化竞态和全局状态污染。双重检查锁、静态内部类等可保证线程安全，但过度使用单例会降低可测试性。

### 4. TCP 三次握手与四次挥手分别解决什么问题？
**解析：**
三次握手建立双向可通信状态；四次挥手是双方独立关闭连接。TIME_WAIT 的存在用于防止旧报文干扰新连接并确保被动关闭方收到 ACK。

### 5. 协程相比线程的核心优势是什么？
**解析：**
协程切换更轻量、创建成本低，适合高并发 I/O。缺点是 CPU 密集任务下仍需多线程或并行执行框架配合。

**参考答案：**

**答案解析：** 处理 TIME_WAIT 要先识别业务模式，不能盲目改内核。

### 简答题 3：请比较快速排序与归并排序在工程中的选择。
**参考答案：**
快排平均性能高、常数小，适合内存排序；归并稳定且适合链表与外排序。选择要看稳定性需求、数据规模、内存约束和输入分布。

**答案解析：** 该题高分点是“场景化选型”，不是机械背复杂度。

### 简答题 4：请解释 HTTPS 握手的关键步骤。
**参考答案：**
客户端发起握手 -> 服务端返回证书与公钥参数 -> 客户端校验证书并协商密钥 -> 双方基于会话密钥加密通信。

**答案解析：** 回答应覆盖“身份验证 + 密钥协商 + 加密通信”三要素。

### 简答题 5：如何系统性减少并发 bug？
**参考答案：**
可从三层治理：
1. 设计层减少共享状态；
2. 实现层使用并发原语和不可变数据；
3. 测试层做压力测试、竞态检测和故障注入。

**答案解析：** 并发治理是体系化工程，不是单点技巧。

### 简答题 6：请描述你处理线上 CPU 飙高问题的排查顺序。
**参考答案：**
先看监控定位时间窗和实例 -> 抓线程栈/pprof -> 识别热点函数与调用链 -> 评估是否死循环、锁竞争或无界重试 -> 修复后回归验证。

**答案解析：** 该题考察排障方法论与工具链掌握程度。

## 三、扩展知识点（问题 + 解析）

### 6. 为什么“时间复杂度正确”不代表“工程性能一定好”？
**解析：**
工程性能还受常数项、内存局部性、序列化开销、系统调用频率和并发争用影响。算法分析是必要条件，不是充分条件。

### 7. 哈希冲突处理策略在工程中如何取舍？
**解析：**
开放寻址和链地址法各有优劣：前者缓存友好，后者删除灵活。选择要看负载因子、删除频率和内存模型。

### 8. 为什么网络编程要重视“超时设置”？
**解析：**
没有超时就没有失败边界，容易造成线程/协程阻塞和资源泄漏。连接、读写、请求级超时应分层配置。

### 9. 操作系统中的“上下文切换成本”如何影响服务吞吐？
**解析：**
频繁切换会消耗 CPU 时间并破坏缓存命中，导致吞吐下降。高并发设计应减少无意义切换和阻塞等待。

### 10. 为什么要区分“可恢复错误”和“不可恢复错误”？
**解析：**
可恢复错误应重试或降级，不可恢复错误应快速失败并告警。错误分级是稳定性治理基础。

### 11. 何为“背压机制”，为什么在并发系统中重要？
**解析：**
背压用于在下游处理能力不足时限制上游生产速率，防止队列无限堆积与系统雪崩。

### 12. 内存泄漏在 Go 与 Java 中表现有何差异？
**解析：**
两者都有 GC，但 Go 常见泄漏表现是 goroutine 泄漏和对象长期被引用；Java 则常见集合持有和类加载器泄漏。GC 不是泄漏免疫。

### 13. 为什么“接口设计”也是编程基础能力的一部分？
**解析：**
接口是协作边界。清晰的输入输出、错误语义和幂等约束能显著降低系统耦合与维护成本。

**答案解析：** 选型不是单看理论复杂度，需兼顾工程现实。

### 简答题 10：如何防止“重试风暴”导致系统被打垮？
**参考答案：**
设置最大重试次数、指数退避+抖动、全链路超时预算、幂等保护与熔断机制；必要时对重试请求限流。

**答案解析：** 受控重试是稳定性设计关键。

### 简答题 11：请描述一次完整的线上故障复盘模板。
**参考答案：**
事故时间线、影响范围、根因分析、处置过程、止损效果、永久修复项、监控补齐项、责任边界与改进计划。

**答案解析：** 复盘重点在“机制改进”，不是简单归责。

### 简答题 12：如何在代码评审中识别并发风险？
**参考答案：**
重点检查共享变量访问、锁顺序、超时处理、异常路径资源释放、幂等与重试交互、channel 关闭责任。

**答案解析：** 并发问题多出现在异常路径与边界条件。

### 简答题 13：请解释“接口幂等”与“事务一致性”的关系。
**参考答案：**
幂等保证重复调用副作用一致，事务保证单次操作内部一致。两者互补：幂等解决重试语义，事务解决原子性语义。

**答案解析：** 理解两者边界有助于设计可靠接口。

### 简答题 14：如何建立服务性能基线并持续监控？
**参考答案：**
定义关键指标（延迟分位数、错误率、吞吐、资源占用），在稳定版本建立基线，发布后做差异对比并自动告警。

**答案解析：** 基线机制能更早发现性能回退。

### 简答题 15：请给出处理“线程池打满”的应急策略。
**参考答案：**
快速限流、降级非核心任务、排查慢任务来源、优化队列与拒绝策略、临时扩容并持续监控恢复情况。

**答案解析：** 应急策略要兼顾止血和根因治理。

### 简答题 16：如何让基础能力建设可持续？
**参考答案：**
把经验沉淀为规范、工具和模板，纳入 CI/CD 门禁，定期复盘更新标准，形成团队级可复用资产。

**答案解析：** 基础能力建设的关键是“制度化 + 工具化 + 反馈闭环”。
