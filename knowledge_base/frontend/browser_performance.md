# 前端工程师 - 浏览器与性能（知识点 + 题库）

## 一、知识点部分（问题 + 解析）

### 1. 浏览器从输入 URL 到页面渲染完成经历了哪些关键阶段？
**解析：**
典型流程是 DNS 解析、TCP/HTTPS 建连、请求响应、HTML 解析、CSSOM 构建、渲染树生成、布局与绘制。性能优化要按链路分段定位，不要把所有问题都归结为JS 太慢。

### 2. 重排与重绘有什么区别？
**解析：**
重排（Layout）涉及几何信息变化，开销更大；重绘（Paint）只改外观不改布局。频繁读取布局属性并立刻写样式会触发强制同步布局，是常见卡顿来源。

### 3. 事件循环中宏任务和微任务如何影响交互流畅度？
**解析：**
微任务会在当前宏任务结束后立即清空。若微任务队列过长，会阻塞下一帧渲染，导致掉帧。前端性能优化不仅是减少任务数量，更要控制任务粒度与分片时机。

### 4. HTTP 缓存中强缓存与协商缓存的关系是什么？
**解析：**
强缓存命中直接用本地副本；未命中再走协商缓存（ETag/Last-Modified）验证资源是否变化。两者是层级关系，不是二选一。

### 5. 前端安全为什么不仅是 XSS 和 CSRF？
**解析：**
现代前端还要关注依赖供应链、CSP 策略、敏感信息暴露、点击劫持和跨域配置误用。安全建设应贯穿编码、构建、发布与运行期监控。

## 二、题库部分（单选题 + 简答题）

### 单选题 1：以下最可能触发重排的是（ ）
A. 修改元素颜色  
B. 修改元素宽度  
C. 修改透明度  
D. 修改背景图

**参考答案：** B  
**答案解析：** 宽度影响布局几何信息，会触发 reflow。

### 单选题 2：微任务队列过长最直接的风险是（ ）
A. DNS 失败  
B. 页面渲染被延后导致卡顿  
C. Cookie 丢失  
D. 路由失效

**参考答案：** B  
**答案解析：** 微任务会在渲染前清空，过长会阻塞下一帧。

### 单选题 3：协商缓存常用的响应头组合是（ ）
A. Cache-Control + Expires  
B. ETag + If-None-Match  
C. Content-Type + Accept  
D. Referer + Origin

**参考答案：** B  
**答案解析：** 协商缓存通过实体标签比对资源是否变化。

### 单选题 4：降低首屏白屏时间优先策略通常是（ ）
A. 延后关键 CSS 加载  
B. 提前加载关键资源并减少阻塞  
C. 增加首屏图片分辨率  
D. 禁用缓存

**参考答案：** B  
**答案解析：** 首屏优化重点是关键路径最短化与阻塞消除。

### 简答题 1：请给出一个前端性能排查的分层方法。
**参考答案：**
可按网络、渲染、脚本、资源、交互五层排查：
1. 网络层看 DNS、握手、TTFB；
2. 渲染层看长任务、布局抖动；
3. 脚本层看主线程阻塞与包体；
4. 资源层看图片体积与缓存命中；
5. 交互层看输入延迟和动画帧率。

**答案解析：** 分层排查可快速定位瓶颈，避免盲目优化。

### 简答题 2：如何平衡性能优化和开发效率？
**参考答案：**
先抓高收益项（首屏、交互关键路径），建立预算（包体、LCP、INP），把优化纳入 CI 和代码规范，再逐步推进细节优化。

**答案解析：** 性能治理应产品化和流程化，不能依赖一次性突击。
